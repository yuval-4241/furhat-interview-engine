# Autonomous Robot Conversation — Design

**Date:** 2026-11-04
**Status:** Built (Plan 2, 2026-11-08); live check pending.
**Builds on:**
`docs/superpowers/specs/2026-11-02-base44-lab-app-integration-design.md`
(Base44 website, `base44_client.py`, `engine_worker.py` MVP).

## Goal

The Furhat robot runs the job-interview conversation itself. It asks the
question, listens, detects when the participant has finished, reacts, and
moves on. Today the researcher types each answer into the website. Under this
design she watches the conversation and approves only the emotional moments.

Success criteria:

- A full session runs from the first small-talk line to the goodbye with the
  researcher only clicking Approve on PBDI turns.
- The robot's facial emotion and speech come from the same engine decision,
  and the website records exactly what the robot's face showed.
- Every design choice stays within the No-Masking constraint: content is
  judged, delivery is never judged.

## Decisions (with the user's reasons)

| # | Decision | Chosen | Why |
|---|---|---|---|
| 1 | Who controls the turn flow | The robot (via the worker), not the researcher | User's goal: a real interview feel |
| 2 | Researcher approval | Before every emotional reaction and every PE feedback line | Keeps a human in the loop on the methodology-critical moments |
| 3 | End of answer | 3 s of silence (`endSil`), max 2 min (`maxSpeech`), 10 s no-speech timeout | Interview answers include thinking pauses, so we don't want to cut people off |
| 4 | Which turns get PE | Only `category = "Behavioral (PBDI)"` | PBDI answers have content worth reacting to emotionally |
| 5 | Opening and closing | Small talk generated by an LLM each session from the dialogue so far | Each session should feel new, not scripted |
| 6 | Approval for small talk | None. Every line is still logged to the website | A paused small-talk exchange sounds unnatural |
| 7 | Non-PBDI Main questions | LLM-generated, content-only acknowledgement. No emotion, no approval | The robot sounds natural without adding unanalysed emotions |
| 8 | After the PE guess | The robot reveals the true emotion and why, after the researcher approves | Training goal: participants learn to read the robot |
| 9 | PE question | Fixed, open free-report: "מה לדעתך הרגשתי, ולמה?" | Same stimulus for every participant. Free labeling is supported by Rosenberg & Ekman 1995 |
| 10 | PE grading | An LLM judge returns Correct/Partial/Wrong from the emotion only. The "why" is commented on but not scored | One score keeps analysis clean. Reasons can still be analysed separately |
| 11 | Near-synonyms | Same-family core words count as Correct. Words closer to another emotion the robot can show count as Partial | Shaver et al. 1987 prototype hierarchy. The robot also shows EXCITED and CALM |
| 12 | Listening technology | Furhat's built-in ASR through a new `/listen` bridge endpoint ("approach 1") | Furhat already handles end-of-speech and not hearing itself. All logic stays in Python |
| 13 | Skill structure | Split into two skills in one multi-module Gradle project that share one `EmotionLibrary` | The calibration study and the interview stop interfering with each other, and they can never show different faces |
| 14 | Per-session face and voice | They come from the website `Persona` (`furhat_face` = Furhat character name, `furhat_voice` = Furhat voice name), applied once per Live session through `/persona`. Once set, `/say` and `/react` no longer override the voice | The researcher picks the persona on the website and the robot matches it, with no code change |
| 15 | LLM model registry | `config.LLM_MODELS` is the single model registry, synced to the website `LLMModel` entity at worker startup | One place to add a model. The website's model list can never drift from what the Engine can actually call |

Future idea, not in scope: a PE confidence rating ("כמה את/ה בטוח/ה, 1–5?")
as a metacognition measure (Brewer et al. 2022).

## Architecture

```
Base44 website (researcher UI + DB)
        ▲  poll every ~6 s / write results
        │
engine_worker.py (Python, researcher's laptop)
  ├─ base44_client.py        — REST, compare-and-set claims, 429 backoff
  ├─ conversation_flow.py    — NEW: per-turn state machine (which step comes next)
  ├─ small_talk.py           — NEW: opening/closing line generator
  ├─ acknowledgement.py      — NEW: content-only reply for non-PBDI turns
  ├─ pe_feedback.py          — NEW: reveal-the-emotion feedback line
  ├─ pe_check.py             — CHANGED: Correct/Partial/Wrong judge
  ├─ evaluator.py, emotion_classifier.py, guardrail.py, response_bank.py — unchanged
  └─ furhat_client.py        — CHANGED: + listen()
        │  HTTP localhost:8765
        ▼
furhat-emotion-study (Kotlin, multi-module)
  ├─ emotion-library/   — shared: EmotionsLibrary.kt, emotions.kt, Interpolation.kt
  ├─ EmotionSkill (root) — calibration study: preview, Test_AU, OBS photosessions
  └─ interview-skill/   — NEW: RemoteControl bridge (/react, /say, /listen, /health),
                          Init → LiveSession directly (no isVirtual(), no preview)
```

`engine_worker.py` stays the orchestrator. It owns the polling loop and
delegates "what happens next in this turn" to `conversation_flow.py`, so the
state machine can be unit-tested without the loop.

## Turn flow

Every turn has a `phase` (`Opening`, `Main`, or `Closing`). Main turns also
have a `category`. The worker processes turns strictly in `order`, and
starts the next one only when the previous turn is `done` or `skipped`.

**Opening / Closing (small talk):**
`queued → robot_speaking (generated line) → listening → engine_processing → done`
The next generated line serves as the robot's response to this answer. The
last opening line leads into the interview. The last closing line is a
goodbye with `expects_answer = false`: `robot_speaking → done`.

**Main, non-PBDI:**
`queued → robot_speaking (question) → listening → engine_processing (ack + guardrail) → robot_speaking (ack) → done`

**Main, PBDI:**
`queued → robot_speaking (question) → listening → engine_processing (evaluate + classify + reply) → awaiting_approval → [researcher Approve] → robot_reacting (emotion + reply) → pe_listening (after the fixed PE question) → engine_processing (pe_check + feedback) → awaiting_feedback → [researcher Approve] → robot_feedback → done`

**`Simulation` mode** keeps the current typed-answer flow (no robot), for
testing without hardware.

## Website contract changes (Base44)

New `Turn.status` values, replacing `awaiting_answer`, `awaiting_engine`,
`awaiting_pe`, and `awaiting_pe_check` in `Live` mode:

| status | set by | researcher sees |
|---|---|---|
| `queued` | app (session creation) | waiting |
| `robot_speaking` | Engine | robot is speaking |
| `listening` | Engine | robot is listening |
| `engine_processing` | Engine | processing |
| `awaiting_approval` | Engine | transcript + emotion + reply, editable, with an **Approve** button → `robot_reacting` |
| `robot_reacting` | app (Approve) | robot reacting |
| `pe_listening` | Engine | listening for the PE answer |
| `awaiting_feedback` | Engine | guess + score + feedback, editable, with an **Approve** button → `robot_feedback` |
| `robot_feedback` | app (Approve) | robot giving feedback |
| `done` | Engine | summary |
| `skipped` | Engine | skipped + reason |

Ownership change: the Engine now writes `participant_answer` and
`participant_pe_answer` (ASR transcripts), plus `question_text` for Opening
and Closing turns. New Turn fields: `skip_reason` (string) and
`robot_line` (what the robot actually said after the answer, for logging).

The question bank, `interview_length` (`Full`/`Short`), and the
`phase`/`level`/`category`/`expects_answer`/`generated_by_engine` Turn
fields come from the Base44 question-bank prompt already drafted on
2026-11-04.

## New prompts (`prompts/`)

The methodology-locked prompts (`EVALUATOR_SYSTEM_PROMPT_A`/`_B`, `PERSONAS`,
`NO_MASKING_FLAG_PATTERNS`) are untouched. All new prompts return JSON.

1. **`small_talk_prompt.py`**
   - Input: phase, position (e.g. 2 of 3), language, and the last 10 turns.
   - Output: `{"line": "..."}`, 1–2 sentences.
   - Warm and casual. No evaluation. No sensitive topics (health, family,
     politics). No emoji.
   - The last opening line transitions into the interview. Closing lines
     thank the participant, ask for questions, then say goodbye.
2. **`acknowledgement_prompt.py`**
   - Input: question and answer.
   - Output: `{"line": "..."}`.
   - References answer content only, then moves on. Never comments on
     delivery (confidence, structure, length, clarity) and never grades
     quality ("great answer").
   - The line is passed through `guardrail.check_rationale()`. If flagged,
     the robot says the fixed fallback "תודה, נמשיך".
3. **`pe_feedback_prompt.py`**
   - Input: target emotion, `pe_answer_why`, the participant's guess, and
     `pe_result`.
   - Output: `{"line": "..."}`, 1–2 sentences.
   - Wording depends on the result (Correct / Partial / Wrong). The reason
     refers to answer content, never delivery.
4. **`pe_check.py` prompt (changed)**
   - Output: `{"result": "Correct"|"Partial"|"Wrong", "explanation": "..."}`.
   - Includes a per-emotion Hebrew word list based on Shaver et al. (1987)
     families, and the rule that a word closer to another displayable
     emotion is Partial.
   - The "why" is commented on in `explanation` but doesn't change
     `result`.
   - **Hebrew word lists need the researcher's review before use.**

## Kotlin changes (`furhat-emotion-study`)

- Convert to a multi-module Gradle build: `settings.gradle` includes
  `emotion-library` and `interview-skill`. The root project stays
  `EmotionSkill`.
- Move `gestures/EmotionsLibrary.kt`, `gestures/emotions.kt`, and
  `gestures/Interpolation.kt` into `emotion-library`. Both skills depend on
  it.
- Move `remote/*` (RemoteControl, ReactionEvent, SayEvent) into
  `interview-skill`. `EmotionSkill` no longer runs the bridge.
- `interview-skill`:
  - Its own `skill.properties`: `language = he-IL`, and it requires a
    microphone and a recognizer.
  - `Init` goes straight to `LiveSession`, with no `isVirtual()` call (that
    call crashed with a NullPointerException on 2026-11-04 when the skill
    started before Furhat was ready).
  - Adds a `/listen` endpoint. The handler queues a `ListenEvent` with
    `endSil`, `maxSpeech`, and `timeout`, and waits on a
    `CompletableFuture` until the flow's `onResponse` / `onNoResponse` /
    `onResponseFailed` completes it. It returns
    `{"text": "...", "status": "ok"|"no_speech"|"failed"}`. The HTTP read
    timeout must be above `maxSpeech`.
- `EmotionSkill` keeps its preview, Test_AU, and photosessions unchanged.

## Error handling

| Failure | Handling |
|---|---|
| ASR returns empty or failed | The robot says "סליחה, לא שמעתי. אפשר לחזור?" and listens once more, then `skipped` (`skip_reason = "no_recognition"`) |
| 10 s no speech | The robot repeats the question once, then `skipped` (`skip_reason = "no_answer"`) |
| LLM call fails | One retry. Small talk / ack fall back to fixed lines ("נעים מאוד, בוא נמשיך" / "תודה, נמשיך"). PBDI evaluation sets `engine_error` and waits for the researcher's Retry |
| Robot bridge down | Wait up to 60 s, then set the current turn's `engine_error = "robot disconnected"` and `robot_connected = false`. The Engine never changes `Session.status` (integration contract), so the researcher pauses or aborts from the website, and Retry resumes the turn |
| Base44 429 / rate limit | Existing exponential backoff (15 s → 120 s) |
| Skill started before Furhat is ready | Removed by design (no `isVirtual()` in `interview-skill`'s `Init`) |

## Testing

- **Python unit tests** with the existing `FakeBase44` plus a fake robot
  (`say`/`react`/`listen`). Every turn type walks every status in order,
  and there are tests for no-speech, empty ASR, LLM failure, and robot
  down.
- **Prompt tests:**
  - The acknowledgement output passes `guardrail.check_rationale()` for a
    set of sample answers.
  - `pe_check` grades fixed Hebrew examples as expected ("כמה מאושר" →
    Correct, "התלהבת" → Partial for HAPPINESS). These are mocked in unit
    tests, plus one real-LLM smoke run with `MODEL_FAST`.
- **Live check** with the robot at the end of each build step.

## Build order

1. **Feasibility spike, before anything else:** add `/listen` to the skill
   and test it alone. Check Hebrew ASR accuracy, a possible ~20 s
   per-utterance cap (reported for Microsoft STT by SahraInterview), and
   whether 3 s `endSil` works. If any of these fail, revisit approach 1 vs.
   2 before building further. If there is a cap, chain listens using
   Furhat's "listening extended" pattern.
2. Split the Kotlin project into multiple modules: create `interview-skill`
   (with `Init` → `LiveSession`) and `emotion-library`.
3. Write the Base44 prompt for the new statuses and fields (alongside the
   question-bank prompt).
4. Worker plus `conversation_flow.py`, in this order: small talk, then a
   non-PBDI turn, then a full PBDI turn. Live-check after each.
5. `pe_check` Correct/Partial/Wrong and the PE feedback, after the
   researcher approves the Hebrew word lists.

## Feasibility results (2026-11-08)

Run by the researcher on the Furhat virtual SDK (launcher, `InterviewSkill`).

- **Gate: passed.** Plan 2 goes ahead as specced (approach 1, Furhat ASR).
- **Hebrew ASR accuracy: good.** Names (שחר, אלכס), numbers ("3 מתח") and
  domain terms ("הנדסה תעשייה וניהול") came through. One misheard word at
  the start of the first probe.
- **Per-utterance cap: none observed.** A ~40 s answer came back whole in
  one `/listen` call, so no listen chaining is needed.
- **No speech:** returns `{"status": "no_speech"}` after the 10 s timeout.
- **Persona:** `{"character": "Isabel", "voice": "AvriNeural"}` changed both
  face and voice.
- **Known issues found during the run:**
  - Recognized text sometimes glues two words together without a space
    ("אחותאחת", "אתהשניה"), apparently at ASR segment joins. Low impact on
    content evaluation; revisit in Plan 2.
  - A bad face or voice name does not return an error. The robot logs a
    warning and keeps the old face/voice, because the face change is
    fire-and-forget. Handled by closed dropdowns on the website (option A);
    server-side validation is a Plan 2 candidate.
  - "Asaf" is not a Furhat voice. Available Hebrew voices: `AvriNeural`
    (male), `HilaNeural` (female), `Hila:DragonLatestNeural` (female,
    untested). Faces (mask `adult`): Alex, Brooklyn, Chen, Dorothy,
    Expresivo, Fedora, Fernando, Gyeong, Hayden, Isabel, James, Jamie, Jane,
    Kione, Lamin, Marty, Maurice, Nazar, Omar, Patricia, Rania, Samuel,
    Titan, Vinnie, Yi, Yumi, Zhen, default.
  - Lipsync server (`ws://127.0.0.1:9001`) was unreachable; speech still
    played.
  - Rebuilding the `.skill` while it runs crashes the JVM (`SIGBUS` in
    `libzip`). Stop the skill in the launcher before rebuilding.
- **Skill fixes made during the run** (`interview-skill`):
  `requiresSpeaker/Microphone/Recognizer = false` (the startup check timed
  out on the SDK), `setInputLanguage(HEBREW)` on entry (the recognizer had
  defaulted to English), and reset to the `default` face on entry.
- **3 s `endSil`:** a 2 s mid-answer pause did not end the listen; the
  text continued after it (confirmed by the researcher).

## Out of scope

- PE confidence rating (future idea above).
- Changing the evaluator, emotion classifier, response bank, or any
  methodology-locked content.
- Question sets for Baseline/Post/Followup, `expression_level` behaviour, and
  the English response bank. These stay open questions in the integration
  doc.
